= Electronic Design Automation with NetApp AFX
:icons: font
:imagesdir: ../media

[.lead]
This technical report covers storage architecture best practices for Electronic Design Automation (EDA) workloads using NetApp AFX. It provides guidance on infrastructure design, performance tuning, and data management to help semiconductor organizations maximize developer productivity and license utilization.

== Abstract

Electronic Design Automation workloads are among the most demanding use cases in enterprise storage. High metadata rates, massive file counts, mixed I/O profiles, and the ever-increasing complexity of leading-edge chip designs push conventional storage systems to their limits. NetApp AFX, built on a disaggregated ONTAP architecture, is purpose-built to address these challenges.

AFX introduces a fundamentally new storage model. The Storage Availability Zone (SAZ) replaces traditional aggregate-based disk ownership with a shared cluster-wide capacity pool, enabling global deduplication, zero-copy volume moves, and independent scaling of compute nodes and NVMe drive shelves. FlexGroup volumes distribute EDA namespace metadata across all nodes simultaneously, eliminating the single-volume hotspots that have constrained NAS performance for decades. NFSv4.x improvements in ONTAP 9.18.1 and later make the protocol a viable — and in many cases preferable — choice for EDA workloads for the first time.

This document describes the AFX architecture as it relates to EDA, covers tiered storage design for semiconductor workflows, and provides best practices for deployment, data management, and hybrid cloud integration.

== How to use this document

This document is intended for storage architects, HPC infrastructure engineers, and IT managers at semiconductor design organizations evaluating or deploying NetApp AFX for EDA workloads. Readers are assumed to be familiar with NFS-based HPC storage concepts and basic ONTAP terminology.

Readers new to AFX should begin with the link:eda-afx-afx-overview.html[AFX architecture] section to understand the platform's unique capabilities and constraints before reviewing the storage design and best practices sections. Readers migrating an existing ONTAP environment to AFX should pay particular attention to the list of features not available on AFX in that section, as several capabilities that are common in unified ONTAP deployments are not present on AFX.

NOTE: This document reflects the AFX feature set as of ONTAP 9.19.1RC1. Some features described — including global deduplication, SnapMirror Active-Sync for NAS, and extended FlexGroup constituent counts — were introduced in that release or the immediately preceding 9.18.1 release. Verify feature availability against your specific ONTAP version before deployment.
