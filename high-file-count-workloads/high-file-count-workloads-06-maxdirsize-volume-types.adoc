= Volume type considerations
:icons: font
:imagesdir: ../media/high-file-count-workloads/

[.lead]
`maxdir-size` applies to every directory in both FlexVol and FlexGroup volumes, but FlexGroup directory entries and constituent layout change how quickly a directory file can grow.

== FlexVol volumes

A FlexVol has one file system and one public inode supply. `maxdir-size` still applies independently to every directory. A single hot directory is processed within that volume's ownership and does not gain parallelism merely because the cluster contains additional nodes.

== FlexGroup volumes

A FlexGroup presents one namespace backed by multiple FlexVol constituents. This improves aggregate file-count scale and enables distribution across nodes and aggregates, but it does not multiply the limit of one logical directory by the constituent count.

Consider the following differences:

* Directory entries can point to files on remote constituents and can require a larger on-disk representation than local FlexVol entries.
* The same visible filenames can therefore consume directory-file space at a different rate than in a FlexVol.
* File and inode capacity is maintained per constituent, so distribution and constituent pressure matter.
* Modify `maxdir-size` on the FlexGroup, not directly on a constituent.
* Sharding an application across multiple directories gives ONTAP more opportunities to distribute work and files.

Do not assume that a FlexVol files-per-directory estimate transfers unchanged to FlexGroup. Include the volume type in every maxdir-size model or migration assessment.

These remote hard links raise the per-directory figure by an amount that scales with the fraction of entries stored remotely. Plan with an upper bound of roughly 2× for large, flat directories (about 85% remote entries), which lowers the practical ceiling to about 2 to 2.6 million names at the 320 MB default versus ~4.3 million on a FlexVol. Wide or deep directory layouts keep the ratio — and the remote hard link inflation — lower. Validate against a representative directory with `stat`, `ls -ld`, or XCP.

== Volume options related to large directories

[options="header"]
|===
| Field | Settable and privilege | Purpose

| `maxdir-size`
| Yes, advanced
| Authorizes a larger per-directory file. Raise only after measuring or modeling need.

| `is-dir-index-transfer-enabled`
| Yes, admin
| Moves directory indexes into public inode space for supported replication and restore portability. It does not enable indexing.

| `has-dir-index-public`
| No, advanced
| Reports whether public directory-index inodes exist.

| `has-optimized-sparse-directories`
| No, advanced
| Reports whether the volume contains optimized hole-punched sparse directories.

| `language`
| Limited, admin
| Controls name interpretation. Non-ASCII and alternate name forms can change directory size behavior.

| `analytics-state`
| Yes, admin
| Enables File System Analytics. Its namespace scans add work on high-file-count volumes but do not change `maxdir-size`.
|===
