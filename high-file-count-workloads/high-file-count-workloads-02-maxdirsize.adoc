= Maxdirsize and large ONTAP directories
:icons: font
:imagesdir: ../media/high-file-count-workloads/

[.lead]
`maxdirsize` limits the size of each directory file in an ONTAP volume by capacity allocated for those names. It is independent of the volume's `maxfiles` inode limit, and there is no static definable limit for number of names in a single directory because that value is variable and based on a number of factors, such as name length, character types, etc. For details, see <link to How maxdirsize is calculated in ONTAP section>.

== What is a directory in ONTAP?

A WAFL directory is a metadata file that maps names to inode numbers. Its size is not the sum of the data stored in the files below that directory, but instead is a factor of the number of names in the directory. A newly created directory starts at 4 KiB and grows in 4 KiB directory blocks as entries are added. 

The directory consumes one inode, whose record is stored in the volume-level inode file (which is separate in concept and function). The directory's names are stored in that directory's own data blocks. Adding more names grows the individual directory file and can approach the `maxdirsize` limit, while creating more file-system objects (such as ACLs) allocates more inode records and can grow the volume-level inode file toward `maxfiles` limits. The number of name entries in a single 4KiB directory block is determined by the size of the name itself.

=== Directory-block layout

An ONTAP directory file grows in 4 KiB blocks, where each block is limited to a variable number of entry records and name chunks based on the size of each. With a 320MB directory size, up to 81,920 directory blocks can be allocated (320MB/4KiB), so the total number of names allowed in the directory file depends on the number of entries allowed per directory block. 

For example, let's say we have a dataset where each block contains:

* 128 entry records of 12 bytes each (1536 bytes)
* 160 name chunks of 16 bytes each (2560 bytes)

Together these occupy one 4 KiB block. Each stored name needs an entry record and one or more name chunks. As a result, neither `maxdirsize / filename-length` nor a fixed files-per-megabyte ratio is exact.

=== Estimating the number of names per directory file

The following calculation can be used to estimate how many files could be placed in a single directory based on the size of maxdirsize and the size of the names themselves.

----
estimated directory-file bytes =
    directory entry count × average on-disk bytes per entry
----

Round the result up to 4 KiB blocks and leave operating margin. The average on-disk entry footprint must account for filename representation, not only the visible character count.

=== Why the number of names varies

The following factors change how much directory-file space each entry consumes:

* Filename length
* ASCII compared with non-ASCII characters
* Unicode long-form representation
* An additional NFS alternate name, when required
* An SMB DOS 8.3 alias, when generated
* FlexGroup remote-entry representation
* Deleted-entry fragmentation and how well new names reuse available slots

This is why there is no absolute number of files allowed in a single directory. Public guidance commonly cites approximately 4.3 million names at a 320 MiB setting for a FlexVol volume, but that would mean the average filename is ~78 standard ASCII characters. === Filename length compared with path length

`maxdirsize` accounts for the basename stored in a particular parent directory. It does not store the entire absolute path with every entry. Each pathname component is an entry in its own parent directory.

A deeper hierarchy adds directories and public inodes, but it reduces the number of names stored in each directory. This tradeoff usually improves scalability. Protocol and client path-length limits still apply independently.

== What maxdirsize actually measures

The volume `maxdir-size` value is the maximum directory-file size allowed for every individual directory in that volume. For instance, a setting of 320 MB means that no directory file in the volume can grow beyond 320 MB. The setting does not reserve 320 MB of volume capacity; it simply grows into that value. A newly created directory starts at 4 KiB, but if that directory file later grows to 320 MB of directory-file blocks, it uses 320 MB of actual volume capacity for those blocks. Once that directory file grows, the directory-file size remains at that high-water mark even if directory entries are removed. Deletion of files or folders makes those entry slots reusable, but it does not compact the directory. Indexed directories can hole-punch fully empty 4 KiB blocks (available in ONTAP 9.5 and later) and reclaim those physical blocks, but the reported directory-file size does not normally shrink. 

=== Raising the maxdirsize value

* Applies to all directories in the volume
* Allows directory files to grow beyond the former cap
* Does not preallocate or reserve the new maximum
* Does not add public inodes or change `maxfiles`
* Does not make an existing directory consume space immediately
